2. Problem Statement
CHALLENGE & MOTIVATION
Campus Scale & Noise Challenges
  • Vast Campus: KEC spans over 167 acres with dozens of academic blocks, food courts, reading lounges, and convention centers.
  • Dynamic Acoustic Fluctuations: Ambient noise varies constantly across study hours due to machinery, food court rushes, and vehicular traffic at gates.
  • Productivity Loss: Students waste 15 to 30 minutes walking across campus searching for quiet revision spots during exams.
  • Static Map Shortcomings: Existing college maps are static and provide zero environmental or acoustic awareness.
Technical & Privacy Dilemma
  • Hardware Cost Barrier: Installing dedicated physical decibel meters across a 167-acre campus is capital-intensive and hard to maintain.
  • Privacy Concerns: Traditional sound apps upload raw voice/audio buffers, causing students to reject microphone permissions.
  • Spatial Search Inefficiency: Exhaustive O(N) linear scanning scales poorly as geographic telemetry points expand.
  • Core Problem: How to provide KEC students with real-time, privacy-guaranteed quiet spot recommendations using existing devices, accelerated by custom 2D Spatial Quadtrees?

3. Domain Background
LITERATURE & FOUNDATIONS
1. Smart Campus Geospatial Systems (GIS)
  • Integrates OpenStreetMap (OSM) vector geometry and verified GPS coordinates.
  • Implements spatial bounding-box containment for KEC [11.2650° to 11.2800° N, 77.5950° to 77.6150° E].
  • Scopes queries strictly to verified campus academic blocks and libraries.
2. Pervasive Crowd-Sensing Telemetry
  • Transforms everyday student smartphones and laptops into passive environmental sensor nodes.
  • Eliminates dedicated hardware costs while achieving high geographic coverage.
  • Enables consensual, anonymous telemetry contributions from study spots.
3. In-Browser Edge Audio Processing (Web Audio API)
  • Hardware-accelerated Digital Signal Processing (DSP) inside the client browser sandbox.
  • Converts PCM Float32 time-domain buffers into Root-Mean-Square (RMS) amplitude locally in RAM.
  • Guarantees zero raw audio storage, recording, or server upload.
4. Spatial Quadtrees & Priority Queues
  • Hierarchical 2D space partitioning decomposing quadrants (NW, NE, SW, SE).
  • Prunes non-candidate search branches in O(log N + K) time vs O(N) linear exhaustion.
  • Custom Binary Min-Heap priority queues power multi-criteria candidate ranking.

Existing Approach Working Mechanism Key Limitations Impact on Students

Generic Maps (Google / Apple Maps) Displays road network, building footprint, and generic navigation routes. Zero acoustic awareness; no indoor noise data; no quiet study recommendations. Helps reach a building, but cannot indicate acoustic comfort inside.

6. Proposed System — QuietSpot 2.0
SOLUTION ARCHITECTURE
1. Distributed Sensing

Leverages students' existing devices without requiring expensive external hardware sensors. Runs purely in modern web browsers.

2. Web Audio Privacy

Calculates Root-Mean-Square (RMS) amplitude locally in volatile memory. Strictly zero raw audio buffers are stored or uploaded.

3. Custom 2D Quadtree

Indexes all campus study spots hierarchically, enabling sub-millisecond candidate pruning in O(log N + K) time instead of O(N) linear exhaustion.

4. Min-Heap Ranking

Combines normalized noise penalty (wN=0.50), walking distance (wD=0.30), and freshness (wA=0.20) ranked via custom binary Min-Heap.

5. Transparent Freshness

Distinguishes Fresh (<30m), Aging (30-120m), and Stale (>120m). Unmeasured locations are penalized transparently rather than assumed quiet.

6. Google Maps Navigation

Generates 1-click turn-by-turn walking route directions from the student's current GPS position to the selected campus study spot.

11. Algorithm & Mathematical Methodology
ALGORITHMIC FOUNDATIONS
1. Custom 2D Spatial Quadtree
  • Decomposes 2D space into NW, NE, SW, SE child quadrants when node bucket capacity K=4 is reached.
  • Prunes non-intersecting quadrants before inspecting candidate points.
  • Circular radius query: bounding-box filtering + Haversine check.
  • Complexity: O(log N + K) query vs O(N) linear exhaustion.
2. Custom Separate Chaining Hash Map
  • Polynomial Rolling Hash: h = (sum(c_i * 31^i)) mod capacity.
  • Separate chaining linked list resolves key collisions.
  • Dynamic resizing: doubles capacity when load factor > 0.75.
  • Average O(1) insertion, retrieval, and deletion.
3. Custom Binary Min-Heap Priority Queue
  • Array-backed binary heap ordering elements by composite penalty.
  • Operations: insert() via sift_up; extract_min() via sift_down.
  • Extracts top-K quiet recommendations in O(K log N) time.
4. Recommendation Scoring Formulation
  • Score = wN * NoisePenalty + wD * DistancePenalty + wA * AgePenalty.
  • Weights: wN = 0.50 (Noise), wD = 0.30 (Distance), wA = 0.20 (Freshness).
  • Haversine Formula: d = 2R * atan2(sqrt(a), sqrt(1-a)), R = 6371 km.
  • Missing Data: 0.65 uncertainty penalty (never assumed quiet).
